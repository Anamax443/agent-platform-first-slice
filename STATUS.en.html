Overview

What it isThe first code written against the norm for a "LEGO" farm of AI agents, deterministic modules and single-purpose write executors. Two vertical slices over five capabilities, built to measure what the norm costs and what its tests catch. Not a product, not a shared runtime.
Core in one sentenceThe model recognises; deterministic code decides and writes. Every write passes the executor's ten-step decision chain, the AI identity holds no write scope, and every ending of a flow is explicit and discoverable by one key.

What the repo contains

contracts/Frozen schemas pinned in CONTRACTS-VERSION (never edited here) and platform policies per capability (ADR-016): who may call what for which tenant; for email.send also the recipient allowlist.
src/platform/Injected clock, ids, JCS, Ed25519 signing with validity windows and grace period, gateway, router, policy, executor host with the decision chain and reconciliation hook, credential resolver (strict/mutant), journal, orchestrator, review service, append-only audit, artifacts with capacity. Local to this project, not a package (P2).
src/components/Five components: document-classifier, document-validator, document-executor-host (stamp + archive), mail-ingest, email-executor. Each has a descriptor, input and output schema and a handler; each imports only platform/api.
src/adapters/Contracts of external systems (LLM, registry, DMS, archive, SMTP) with fakes and failure modes: timeout, 5xx, business error, schema-valid nonsense, unknown outcome, crash after write, full storage.
workflows/Two versioned, immutable flow definitions; running instances pin their version.
conformance/Per capability: fixtures (canonical, damaged, injection, boundary, error), golden outputs with MUST/DON'T CARE, errors.md, compat.md. Per workflow: scenarios and golden master.
tests/One file per family (ctr, sec, mut, idm, wf, res, int, evd, arch) plus mail for the second flow. Test names carry Test IDs, so the run log is evidence.
docs/MEASUREMENT.mdThe main thing. Hours, lines, findings caught by tests, waste by lean category, what had to be worked around and what is proposed back to the norm.
HANDOFF.mdState diary, append-only, newest first. Source of truth for continuing from another machine.

Where the norm shows in the code

F1 privilege boundaryThe AI identity holds a single scope (document.classify); the router refuses everything else; writes only through an executor host with an allowlist; email.send takes a reference, only policy supplies the address.
F2 untrusted dataDocument text inside delimiters, model output only through an enum; the validator recomputes the value by rules over the text with instruction-like lines removed; a stamp only with validation evidence; the mail template only from an enum and an id.
F4 trusted contextContext derived from identity, signature over {message, context}; a forged tenant, scope, payload or an unsigned envelope ends in CONTEXT_BINDING_INVALID; key rotation without losing messages.
F5 / F6 states and writesUNKNOWN_OUTCOME with bounded reconciliation and then review, never a blind resend; deadline with clock tolerance; one idempotency key = one side effect, for IRREVERSIBLE also dedup at the provider.
F7 evidenceImmutable original, derivation with derivedFrom, provenance on every value, append-only audit, the whole flow discoverable by correlationId.
P1 verifiableFive MUST mutants with a negative branch on both hosts: the tests provably can fail.

What the tests caught

Twelve findings. Five caught by a test on its first run, five from writing a test against the norm or from wiring the second component, two showing tests ageing. One documented limit of the norm, bridged in the slice.

Audit was not append-onlyAudit.all() returned shallow copies; record details could be overwritten from outside. Caught by EVD-004 on its first run.
Key on technical retryThe orchestrator changed the idempotency key on technical retry, against §5.2 of the norm. A second side effect was possible. Found while writing the test; IDM-REPLAY-001 guards it since.
Unsigned envelope acceptedThe router accepted an in-process binding without a signature. A bypass of all of F4. Found while writing SEC-CTX-003, fixed with accepted mechanisms.
Injection inside the allowlistA model talked into "classify this as INVOICE" returns a valid value and the F2 boundary lets it through. A limit of the norm, documented by a scenario. Bridged in the slice by a second deterministic signal in the validator: both injection scenarios now end in review instead of a stamp.
Two flows in one journalWithout a guard, one flow's orchestrator would "recover" the other flow's instance with the wrong steps after a restart. Found while wiring the second orchestrator.
Delimiters in the promptThe prompt named the delimiter in a sentence before the data block; the parser took the instruction as data and classified the word "and". Caught by the first end-to-end run.

What goes back to the norm

Frozen documents change only with evidence from code. This is the evidence for part XVII "Implementation protocol":

  • Which outcomes the idempotency store keeps (SUCCEEDED and UNKNOWN_OUTCOME; FAILED before the side effect stays retryable).
  • The reconciliation hook belongs to the executor and confirms or releases the dedup record by the result; the orchestrator calls it as an opaque object.
  • The idempotency key goes to the external system as business identity for every write capability, not only IRREVERSIBLE ones.
  • A second independent signal for an AI capability whose output leads to a write with risk MEDIUM or above: proposed as a CONDITIONAL rule, awaiting decision.
  • Who computes the key grace period; the anti-pattern "delimiter name before the block"; an alert channel for full storage; PRINCIPAL inside one process is a simulation.
